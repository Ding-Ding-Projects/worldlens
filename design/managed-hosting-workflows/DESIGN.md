# Managed world and hosting workflows

Design baseline: `49d009b5ad685022abbb47dcff00b43305589ba8`. Maintained viewer baseline: BlueMap `fcfea026` on `material-design-3`. This reference specifies implementation behavior; it is not production runtime, layout, security or release evidence.

## Product structure

Keep the existing project workspace and navigation. Add the primary **Generate and start project** action directly to the Projects new-project card, Home's world action group and World's source actions. All three open one coordinator and restore its same draft. Retain **Open existing world** alongside it. Creation opens the resulting project's productive workspace, never a promotional screen. One workspace tab owns one stable project identity; selecting it again focuses it. Utilities open in a new tab only through an explicit New tab catalog choice.

The project workspace has task tabs: **World**, **Configuration**, **Access**, **Renders**, **Map**, **Hosting**, **Bots**. A compact project header contains name, server connection state, product version/build update time and contextual actions. Keep selected project, active tab, run selection and unsaved drafts across destination changes. Each workflow reports progress where it started and in the existing global activity surface. Navigation does not cancel background operations.

Normal desktop is 1440×900 CSS pixels. At 800×600, use one content column, wrap actions, allow the document body to scroll and keep only the active panel mounted. Tool dialogs become viewport-bounded full-height sheets with a scrollable body and visible action row. Hosted 320-pixel layouts put viewer tools in a bottom sheet with a compact action bar; the map retains usable space. Never shrink text, clip fields or require horizontal page scrolling to fit translated content. Scale is applied by the host, not a transform on the application root.

## Genuine component strategy

The workspace already uses Vue 3.5 and Vuetify 3.13. Reuse its provider, theme and local fonts. Use imported `VCard`, `VToolbar`, `VTabs`, `VWindow`, `VBtn`, `VMenu`, `VList`, `VDialog`, `VTextField`, `VSelect`, `VAutocomplete`, `VSwitch`, `VCheckbox`, `VSlider`, `VDataTable`, `VAlert`, `VChip` and progress components. Use the shared design-system theme, not new hard-coded color values. The reference imports actual Vuetify primitives and the existing `ConfigSearchField`.

Both viewer surfaces need a common Vue `ViewerChrome` composition bound to a small controller interface. Worldlens mounts it around `MapView.vue`; maintained BlueMap mounts it around its existing canvas through an adapter and adds the actual Vuetify dependency/provider. Remove competing raw-DOM chrome from `materialShell`, not the Three.js renderer, geometry, tile loader or canvas. Canvas is functional geographic output, not a substitute button, menu or dialog. Audit every visible primitive in both surfaces; a custom HTML lookalike is an unresolved defect.

Reuse `ConfigField` and its list/object/record dispatch for configuration semantics. Reuse `MarkerStudio` geometry and validation, but change primary editing from JSON points to direct map drawing. Reuse the anchored `ConfigSearchField` composition independently per search. Its current builder is not a claim of complete RegexBuddy parity: retain a topic-by-topic implementation/evidence ledger for construction, analysis, flavor/version binding, match/replace/split, debugger, benchmark, code generation/templates, collections, file operations, history, integration and preferences. Missing capabilities stay explicit and unfinished.

## Generation

Wizard steps: **Destination → Edition and distribution → World → Extensions → Review → Generate**. Default to local Java vanilla, persistent destination and pregeneration off. Catalogue-backed selectors include release/snapshot/version, flavour and exact distribution revision with source and compatibility. Preserve full seed as text with resolved numeric value where applicable. World controls include preset, biome, terrain/noise settings, dimensions, structures, ordered superflat layers, borders and spawn. Extensions include compatible datapacks, mods/plugins, game rules and pregeneration method/radius with resource estimate. Dynamic capability descriptors carry type, default, bounds, availability reason and the actual execution consumer; no invented universal list.

Destination supports the four existing execution targets: local process, local container, SSH process and SSH container. Generation's first supported default remains local vanilla; other rows show their actual implementation and compatibility state. Existing-folder collisions require a new owned destination or explicit reviewed adoption, never overwrite. Review names exact distribution, destination, disk estimate, download/license consent and operations. EULA consent is explicit and separate from starting.

The coordinator resolves dependencies, obtains authorized downloads, launches the owned server, observes readiness, optionally pregenerates, stops and saves gracefully, probes the real world, creates the durable project, reads it back, then opens World. Synthetic quick-test remains a separately named mode. Progress distinguishes downloading, starting, generating, saving, inspecting and creating project. Cancel requests a safe stop, reports completed effects and preserves recoverable output; it never reports rollback merely because the dialog closed. Failed project persistence offers **Retry project creation** against the verified output instead of generating again.

## Configuration

A searchable file list and independent searchable field list show the selected server/version/flavour. All supported files call the same describe/apply service. Dispatch on actual type: switch, enumerated selector, numeric field/slider, literal text, nested object, list or record table. Never coerce collections through `String(value)`. Preserve unknown fields/comments, null/boolean/number distinctions and strict JSON. Unknown schema has an explicitly labelled advanced editor and an unfinished descriptor row, never a false typed-editor claim.

Explicit record tables cover `ops.json`, `whitelist.json`, `banned-players.json` and `banned-ips.json`. Player records use UUID/name identity selection; operator level and bypass-player-limit use typed controls; bans include source/reason/creation/expiry with timezone and permanent-expiry handling. IP bans use validated addresses, not a player picker. Add/edit/remove work in a draft with validation and a reviewable diff. Apply sends expected source hash/revision. Conflict presents **Reload latest**, **Compare** and **Reapply reviewed changes** while preserving the user's draft; no last-writer overwrite. Reset means reset draft or selected values to documented defaults, never silently alter a live server. Show each setting's live/restart status.

## Access before rendering

The Access step is required before a new render begins. Collect administrator username and password in protected controls, with localized validation, clear controls and no value echo in summaries. Preparing access creates a salted memory-hard verifier through the protected local service and stores only an opaque credential reference in the project. Do not put verifier/password/session material in project JSON, map assets, images, exports, logs or history.

Three separate state badges: **Prepared on this device**, **Provisioned on destination**, **Sign-in verified**. Preparation does not imply an account exists remotely. Destination provisioning uses one-time protected bootstrap at deployment, outside the portable export. Expired/used bootstrap retries create a fresh operation through the protected channel. Shared viewers require sign-in by default. Only an authenticated owner can choose public read access; public read does not enable edits. Account and annotation storage remain separate from read-only map assets. Network authentication requires the protected transport; a missing secure endpoint is an actionable incomplete state.

## Render selection and internal map

The **Which render** picker belongs above the map and in Renders. It has its own plain-text default search, adjacent independent anchored regex builder, real project/render labels, engine, dimension, creation time and lifecycle. Do not select a different project implicitly. Each row shows **Running: partial preview**, **Engine finished**, **Verifying**, **Retained and verified**, **Interrupted** or **Verification failed**. Only verified retained records are represented as complete. **Open map** opens/focuses the internal destination; **Open externally** is secondary.

Keep immutable run ID, stable project ID and effective map ID distinct. Resolve upstream map-ID normalization once and reject collisions before work. Existing output recovery verifies source/session/output binding, backs up the record and revalidates before promotion. Never weaken provenance because a folder happens to exist. A running view follows its run and transitions to its verified retained result without replacing the workspace or losing camera state when the same map remains valid.

Blank-map recovery is diagnostic, not a successful render badge. Show actual configuration/tile/texture/WebGL/camera observations, **Fit available terrain**, **Retry resources**, **Show render details**, and **Choose another render**. Distinguish no generated terrain yet, missing assets, wrong map identity, unavailable endpoint and renderer failure. Retry only the failing stage. Do not invent the cause or substitute an image for terrain.

## Map editing and server actions

Toolbar: **Markers**, **Draw area**, **Commands**, **Bots**, with view controls separate. A shared spatial picker supplies point, rectangle, polygon, path, height/range and dimension operands. Picking suspends camera gesture only for that mode; Escape cancels the current pick and restores focus, Enter confirms valid geometry, Backspace removes the last vertex, and Undo/Redo applies within the active draft. An explicit coordinate table is an equivalent keyboard route. Show coordinate system, world/dimension and selected server throughout.

Markers support POI, line, shape and extrusion, vertex dragging/insertion/removal, numeric alternatives, style, label and preview. Review before save. Local project persistence and hosted revisioned storage use the same logical document. Authenticated viewers see shared edits; stale revision returns a conflict that retains the draft and offers comparison/reload/reapply. Offline drafts are clearly unsynchronized and are never silently committed on reconnect.

Commands come from the selected server's complete discovered graph, including redirects, permissions and plugin nodes. Discovery has source/version/time and completeness state. Typed parsers provide actual enum/registry suggestions, target identity, bounded numeric/boolean/text inputs and spatial operands. Nested commands preserve their graph path. Unknown parsers are explicitly unsupported, with raw copy as an expert fallback that does not imply safe execution or graph completeness. Player context resolves a real UUID/server association, then opens the same workflow. Missing/stale identity prevents execution. Preview exact command, target and affected geometry before authorized execution; apply existing destructive confirmation to consequential changes. Never execute merely by selecting a point. Include teleport, setblock, fill and clone as required examples, not a finite command catalogue.

## Hosting and publication

Hosting starts from a specific verified render. Outcomes are **Native host**, **Container host**, **Build image**, **Save image archive**, and **Upload image**. Native includes direct process and selected WSL route. Both hosts use the same authenticated map/annotation service and separate writable state. Container delivery includes immutable image association, tracked Compose, detached/log entrypoints and tailored portable setup wizard. Health and intended LAN URL require actual checks.

Build, save, sign-in and upload are independent actions. Save returns the actual archive path/hash. Upload opens a review containing registry (default `docker.io`), namespace, repository, tag, source/image identity and visibility. Device sign-in shows only the supported URL/code and expiry; it does not upload. An explicit **Upload reviewed image** is the only publishing action. Show build, saved, uploaded and pull/start verified separately, with exact digest readback. No account material enters image layers or archives. Upload cancellation reports the actual registry state rather than assuming nothing transferred.

## Bots

Two distinct profile cards: **Mineflayer** (optional pathfinder) and **Baritone Java client**. Each has independent server/account/version compatibility, deployment and health. Mineflayer's currently documented ceiling is 26.1; 26.3 is unavailable until verified adapter evidence exists. Baritone uses a genuine supported client distribution, not a Mineflayer label. Wizard steps choose profile, server, compatible version, protected account sign-in, capabilities and reviewed deployment. Start/stop/reconnect target only the owned bot process. Navigation consumes the shared map picker, shows current goal/path/status and supports cancel. A lost connection is not a stopped bot. Sanitized logs omit authentication data.

## Interaction and accessibility contract

Use English, written Cantonese and bilingual labels from localization keys; bilingual stacks the second label rather than compressing font size. Preserve existing tone/language controls. Every capable control has a target-specific 44-pixel info icon directly above it, opening optional explanation, guided steps, isolated worked example and resettable playground. Contextual help never reads live credentials or performs a real action. Implement help through one target descriptor per control, not generic repeated text. The reference's small sample help is only composition guidance; production coverage requires the control inventory.

Use visible focus and natural order; tab strips use roving focus, menus arrow navigation, dialogs labelled titles and focus return. Cancellation does not discard unsaved drafts without the existing protection. Errors are inline plus polite live notification, never blocking toast loops. Reduced motion disables travel/zoom animation and preserves outcomes. Loading/offline/empty/conflict/canceled/error states have an exact next action and retain valid input. Existing appearance, accessibility, export, history, command palette and tab-management behavior remains available through shared providers, with each added surface included in coverage.

## Shared server attempt, hosting status and console

All server surfaces consume one server runtime observation store keyed by stable server ID and current attempt ID. Each launch receives a new attempt identity; console subscriptions, readiness, process exit, hosting badges and operation progress retain that identity. Starting is not running: readiness comes from the actual current attempt. A disconnected observer reports unavailable observation while retaining last observed lifecycle and timestamp; it never changes the server to stopped.

On start, show **Starting** with the exact owned attempt, then attach its console and update all surfaces from the same event stream. On readiness, refresh the server snapshot and attach/rebind the current console even if its initial subscription predated launch. On an exit event, compare event attempt to the current attempt before changing lifecycle. A late exit from an earlier attempt cannot stop the new attempt or detach its console. Record the stale event as historical and refresh the current snapshot. A confirmed current-attempt exit updates hosting, server list and console together, showing real exit result and a retry action bound to a new attempt.

Reconnect UI keeps last observed state and clearly says **Connection unavailable**, with **Refresh current attempt and reconnect**. Read the current authoritative snapshot first, dispose the obsolete subscription, then attach the current attempt with a cursor to avoid missing or duplicating messages. If a newer attempt is discovered, show that transition; never replay old control commands. Lost SSH observation is not proof of process exit. Refresh failure retains the unavailable state and a bounded retry control.

For an owned local process, unavailable RCON does not disable its stdin console. Show **Local console available; RCON unavailable**, with transport and owned attempt identified. Route validated console submission to that current owned stdin handle; confirm the same attempt immediately before sending and reject a stale target without automatic replay. If neither transport is available, keep the draft and explain which connection is missing. Never expose credentials, enable insecure RCON or treat an unrelated process as a fallback. Command-builder execution still uses the selected authorized backend, permissions and destructive-action review.

The design reference has deterministic `generation/reconnecting`, `generation/late-exit` and `generation/stdin-fallback` fixtures. They show current and event attempt identities separately and demonstrate refresh/rebind and local stdin preview without launching or writing to a real server. Production acceptance must exercise start-before-subscribe, reconnect during startup, old exit after new launch, current exit, unavailable RCON with valid owned stdin, and stale stdin rejection. Every observation assertion checks the hosting badge, server list and console against the same current attempt.
